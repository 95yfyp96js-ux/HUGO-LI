# BOSS-SPEC — 第 1 版規格（小額借款＋支票貼現）

> 產品一句話：**小額借款＋支票貼現。員工把今天的事登進去並核銷到正確的一期或
> 一張票；線上隨時有活盤；每天結帳並由我認證鎖死；週月報只加總已認證日結。**
> 第 1 版 = 一個網址，電腦與 iPhone Safari 同一套。

本文件是**行為契約**，不是願景。每一條要嘛是可執行的規則，要嘛標成「規格缺口」
等人決定。沒有第三種。

---

## A. 角色（第 1 版只有兩種，沒有第三種）

| | 員工 | 老闆 |
|---|---|---|
| 新增客戶 | ✅ | ✅ |
| 新增借款／確認撥付 | ✅ | ✅ |
| 收票／收款核銷／兌現核銷／退票轉追償 | ✅ | ✅ |
| 看自己今天的流水 | ✅（**只有自己的**） | ✅（全部人的） |
| 看全部活盤五格、點進每一筆 | ❌ | ✅ |
| 核定／確認／**認證日結** | ❌ | ✅（認證僅老闆） |
| 看更正單 | ❌ | ✅ |
| 改已認證資料 | ❌（任何人都不行，包含老闆） | ❌ |

兩條寫死的：

1. **認證是老闆專屬且不可代理。** 系統沒有「代為認證」「授權他人認證」的介面。
   要換人認證＝改角色設定，該動作本身留痕。
2. **已認證營業日的資料，任何角色都不能改。** 老闆也不行。只能開更正單（見 F）。

## B. 員工按鈕：**最多 8 個，寫死名稱，沒有第 9 個**

按鈕名稱即畫面文字，不得改寫、不得加子選單塞第 9 個動作。

| # | 按鈕名稱 | 必須選到什麼才能存 | 存不下去時畫面顯示（原文） |
|---|---|---|---|
| 1 | `新增客戶` | 姓名、證號 | 「這個證號已經有客戶了：<姓名>（末四碼 ****1234）。要用同一位客戶請直接選他。」 |
| 2 | `新增借款` | 客戶、本金、利率、期數、還款方式 | 「金額必須大於 0，最多兩位小數。」／「期數必須是 1 以上的整數。」<br>**畫面不手填每期金額**，計畫由計息規則產生（見「本機封存」） |
| 3 | `確認撥付` | 借款、實際撥付日 | 「撥付日不可以是未來日期。」／「這筆借款已經撥付過了（<日期>），不能再撥一次。」 |
| 4 | `收票（貼現）` | 客戶、票號、行庫、票面、到期日、收票日、貼現息、實付 | 「這張票已經收過了（票號末四碼 ****5678，收票日 <日期>）。」／「實付 ≠ 票面 − 貼現息 − 其他費用，差 <金額>，請把數字改到相符或填『其他費用』。」 |
| 5 | `收款並核銷` | **哪一筆借款的哪幾期**（loan_id + schedule_seq，至少一期） | 「請先選到要沖銷的期別，沒有選期別的收款不能存。」／「這筆錢超過應繳，多出 <金額>，請先確認去向。」（見 C-2） |
| 6 | `票兌現並核銷` | **哪一張票**（check_id）、實收金額 | 「請先選到要兌現的票。」／「實收與票面差 <金額>，請選差額原因。」／「這張票目前不是『持有』狀態（現為：<狀態>），不能兌現。」 |
| 7 | `票退票並轉追償` | **哪一張票**（check_id）、追償金額 | 「請先選到要退票的票。」／「這張票目前不是『持有』狀態（現為：<狀態>），不能退票。」／「追償金額與票面不同，請填原因。」 |
| 8 | `看今日流水` | — | 「今天還沒有任何紀錄。」 |

**共同失敗顯示規則**

- 錯誤訊息一律說「**哪一筆、差多少、下一步做什麼**」。禁止「操作失敗」「請稍後再試」
  這種沒有資訊量的字。
- 金額一律顯示到分（`NT$8,884.88`）。**禁止在任何可操作畫面顯示整元。**
- 存檔失敗時**保留使用者已填的內容**，不清空表單。

## C. 核銷規則（＝對帳鍵，不准模糊）

### C-0 共同：唯一鍵與防雙擊

| 機制 | 內容 |
|---|---|
| 冪等鍵 | 每個寫入表單**在打開時**產生 `op_id`（UUID v4），送出時一併帶上。`operations` 表 `UNIQUE(op_id)`。第二次送出同一個 `op_id` ⇒ 不再寫入，直接回傳第一次的結果。**雙擊、網路重送、iPhone Safari 上一頁再送，全部只成立一次。** |
| 狀態變更 | 一律用條件更新（compare-and-set），不先讀再寫：<br>`UPDATE checks SET status='cashed' WHERE check_id=? AND status='held'`<br>影響列數 = 0 ⇒ 整筆交易回滾，回「這張票目前不是『持有』狀態（現為：X）」 |
| 票的唯一性 | `UNIQUE(bank_code, check_no)` — 同一張票不可能被收兩次 |
| 期別不可超收 | `UPDATE schedule_items SET paid = paid + ? WHERE loan_id=? AND seq=? AND paid + ? <= due_total`<br>影響列數 = 0 ⇒ 整筆回滾（該期已被別人沖過了） |

`op_id` 在**表單開啟時**產生，不是在按下送出時產生 — 這是關鍵。後者擋不住雙擊。

### C-1 借款收款核銷

- **對帳鍵：`loan_id` + `schedule_seq`。** 一筆收款可對應多期，每一期一列分配明細，
  `UNIQUE(op_id, loan_id, schedule_seq)`。
- 期內金額進**固定瀑布**：`罰息 → 費用 → 利息 → 本金`，**全程整數分**。
- 由舊到新逐期沖銷。
- 每一期的分配結果各自寫一筆流水（entry），不是只寫一筆總額 — 否則重放時無法還原
  到期別。

### C-2 溢繳

- 沖完所有未清期別後仍有剩 ⇒ **不入帳**，先回 `NEEDS_CONFIRM` 並列出：本次收款、
  沖罰息／息／本各多少、還多出多少、這筆錢會記成負向調整分錄待人工處理、
  **本版沒有自動退款流程**。
- 使用者按確認後，請求帶 `overpay_ack = true` 重送（同一 `op_id`）才寫入。
- 沒帶 `overpay_ack` 的溢繳請求**一律不寫**。禁止默默入帳。

### C-3 票兌現

- **對帳鍵：`check_id`。**
- 實收應接近票面。`|實收 − 票面| > 0` 時**必須選差額原因**：`手續費 / 部分兌現 / 其他`，
  選「其他」必填文字。沒選 ⇒ 不能存。
- `部分兌現`：票**不轉「已兌現」**，維持持有並記錄已收金額；剩餘部分仍算未收。
- 狀態轉移：`持有 → 已兌現`（條件更新，見 C-0）。

### C-4 票退票並轉追償

- **對帳鍵：`check_id`。**
- 狀態轉移：`持有 → 退票追償中`（條件更新）。
- 追償金額**預設 = 票面**。可改，**改了必留原因**（原因為必填字串，寫進流水）。
- 退票不刪除原本的收票紀錄。收票、退票、追回是三筆流水，不是改同一筆。

### C-5 重複狀態變更

同一 `loan_id + seq` 的同一次沖銷、同一 `check_id` 的同一個狀態變更，
**第二次一定失敗**，靠的是上面的 `op_id` 唯一鍵 + 條件更新，
不是靠前端 disable 按鈕（前端擋不住重整與雙裝置）。

## D. 活盤五格（每格 = 公式）

前提：所有金額整數分；`today` = 營業日。

| # | 格名 | 公式 |
|---|---|---|
| 1 | 在外借款本金 | `Σ LOAN_DISBURSE.principal − Σ LOAN_COLLECT.principal ± Σ LOAN_ADJUST.principal`，下限 0 |
| 2 | 未到期票面合計 | `Σ CHECK.face WHERE status='持有' AND due_date > today` |
| 3 | 今日應收 | `Σ(schedule_items.due_total − paid) WHERE due_date = today AND 未清`<br>`+ Σ CHECK.face WHERE status='持有' AND due_date = today` |
| 4 | 今日已收 | `Σ LOAN_COLLECT.amount WHERE posted_date = today`<br>`+ Σ CHECK_CASH.received WHERE posted_date = today` |
| 5 | 逾期＋追償 | `Σ(due_total − paid) WHERE due_date + grace < today AND 未清`<br>`+ Σ CHECK.recourse_outstanding WHERE status='退票追償中'` |

### D-1 這五格必須能用流水重放得出

每一格都有兩條算法：**現況表直接查**，與**從第一筆流水重放到今天**。
系統每次載入活盤時兩條都算，比對。

**對不上時，畫面直接打「盤不平」**，紅字列出差多少、差在哪一格、
最後一次對得上的營業日是哪天。

**禁止顯示 0、禁止顯示上一次的快取、禁止四捨五入把差額抹掉。**
差 1 分也是不平。

### D-2 已知規格缺口（要老闆決定，不准我自己補）

> **缺口 G1：持有中但已過到期日、還沒兌現也還沒退票的票，沒有格子。**
> 格 2 只算未到期，格 5 只算退票追償中。這種票會從五格裡消失。
> **第 1 版的處理：不消失也不亂塞** — 它一定會出現在「今日未核銷的到期項」紅字
> 清單，且該清單非空時不能認證（見 F）。要不要把它算進格 5，請老闆決定。

## E. 日結（一張表，不是儀表板裝飾）

| 區塊 | 欄位 |
|---|---|
| 表頭 | 營業日、產生時間、產生者 |
| 期初五格 | 在外借款本金、未到期票面、今日應收、今日已收、逾期＋追償（＝昨日期末，直接抄過來） |
| 本期進出 | 放款（撥付金額）、收款（借款核銷金額）、收票實付、兌現（實收）、退票（轉追償金額） |
| 期末五格 | 同五格定義，以當日收盤重算 |
| 不平項目 | 每一項：類型、對象（loan_id+seq 或 check_id）、應為、實為、差額 |

### E-1 硬規則（違反就不能認證，不是警告）

1. **昨日期末五格 ≠ 今日期初五格 ⇒ 不可認證。**
   （中間有人動了已鎖的資料，或前一日根本沒結。）
2. **本期流水重放 ≠ 期末五格 ⇒ 不可認證。**
   逐格檢查：`期初 + 本期進出 = 期末`。任何一格對不上就擋。
3. **今日有未核銷的到期項 ⇒ 可以核定，但認證畫面必須紅字顯示**（見 F）。

### E-2 週報／月報

**＝該區間「已認證日結」的加總。就這樣。**

- 未認證的日子**不算進去**，並在報表上列出「本區間有 N 天未認證：<日期清單>」。
- **不做第二套月結引擎。** 月報不重新計算、不重新重放、不從流水另外算一次。
  月報唯一的資料來源是日結表。兩套引擎＝兩個答案＝以後永遠在對帳。

## F. 四關（人按，系統只攔截）

| 關 | 誰按 | 系統做什麼 |
|---|---|---|
| **核定** | 內勤或老闆 | 產生當日日結快照，記錄「這張日結我看過」＋按的人＋時間 |
| **核銷檢查** | 系統自動 | 列出「今日未核銷的到期項」：到期未收的借款期別、到期未兌現的持有票、逾期未處理的票。**有未核銷仍可核定**，但這張清單會一路帶到認證畫面 |
| **確認** | 老闆 | 記錄「盤我對過」＋時間。此時畫面必須同時顯示未核銷紅字與不平項目 |
| **認證** | **僅老闆** | 通過後該營業日**鎖定**。鎖定後任何寫入都被拒 |

### F-1 認證前的攔截條件（系統擋，不靠人記得）

- E-1 第 1、2 條任一違反 ⇒ 認證按鈕**不能按**（disabled 且寫明原因）。
- 未核銷清單非空 ⇒ 認證按鈕**可以按**，但畫面上方必須是紅字：
  「今日有 N 筆到期項未核銷，認證後這些項目會留到明天。確定要認證嗎？」
  老闆按下去＝他知道並承擔。系統不替他決定，但也不讓他看不到。

### F-2 鎖定後：只能開更正單

更正單欄位（全部必填，除了「新狀態」與「新金額」擇一）：

| 欄位 | 說明 |
|---|---|
| `original_entry_id` | 要更正的原分錄 id |
| `new_amount` / `new_status` | 新金額或新狀態（擇一） |
| `reason` | 原因，自由文字，不可空白 |
| `operator` | 操作者 |
| `created_at` | 時間 |

**更正單的三條鐵律**

1. **不回頭改已鎖日結。** 已認證的那一天，數字永遠是那天認證時的樣子。
2. **更正單本身列入「下一個營業日」的流水**，會被下一日的重放算進去、
   出現在下一日的日結「本期進出」裡。
3. **原分錄不刪除、不覆寫。** 原分錄與更正單並存，兩筆都看得到，
   誰、何時、把什麼改成什麼，事後可完整重放。

## G. 票據欄位（最小值）

| 欄位 | 說明 | 畫面 |
|---|---|---|
| `customer_id` | 客戶 | 姓名 |
| `bank_code` | 行庫 | 完整 |
| `check_no` | 票號，**存完整** | **只顯示末四碼 `****5678`** |
| `face_amount` | 票面（分） | 到分 |
| `due_date` | 到期日 | — |
| `received_date` | 收票日 | — |
| `discount_interest` | 貼現息（分） | 到分 |
| `cash_paid` | 實付（分） | 到分 |
| `other_fee` | 其他費用（分，預設 0） | 到分 |
| `status` | `持有` / `已兌現` / `退票追償中` / `已追回` | — |
| `settled_at` | 核銷時間（兌現或追回的那一刻） | — |
| `recourse_amount` / `recourse_reason` | 追償金額與改動原因 | — |

### G-1 兩條寫死的

1. **恆等式：`實付 = 票面 − 貼現息 − 其他費用`。** 不符合就不能存（見 B-4）。
2. **不准用借款的月付公式套票。** 票是「一次到期的票面 − 前收貼現息」，
   不是分期攤還。禁止在票據流程呼叫任何攤還／年金函式。
